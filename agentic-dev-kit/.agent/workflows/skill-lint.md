# Skill 质量治理 (Skill Lint & Evolve)

> 触发方式: `/skill-lint [scope]`
>
> **来源**: 对照 ATA「skill-lint v0.2.0」原始内容校准：
> - 原始 skill-lint: **5 大质量维度 100 分制** (清晰边界25/确定性执行20/可失败回退15/解耦可组合20/包完整性20)
> - 原始 skill-lint: **37 条规则 ID** (CB-01~CB-05, DE-01~DE-02, FF-01~FF-03, DC-01~DC-03, PI-01~PI-04, SC-01~SC-06, ENG-01~ENG-02)
> - 原始 skill-lint: **只读扫描** — 扫描过程严禁修改任何文件，除非用户在报告后明确要求修复
> - 原始 skill-lint: **修复模式门控** — 仅当用户说"帮我修复/fix"时才进入修复模式
> - 原始 skill-lint: **降级方案** — lint-rules.md 读取失败时使用内置基础规则继续扫描
> 结合现有 `skill-audit.sh` 的基线检查能力和本体系的 12 维度补充评估。
>
> **强制规则**:
> - ❌ **只读扫描**：扫描过程严禁修改任何文件
> - ❌ **不运行 Skill**：纯静态分析，不实际执行 Skill 的工作流或脚本
> - ✅ **基于规则检测**：所有检测项基于规则定义，不凭空判断
>
> **与现有流程关系**:
> - `skill-audit.sh` 提供**基线扫描**（文件存在性、frontmatter、长度）→ 本流程的 Step 1
> - `/evolve` 负责 Rule/Skill **生命周期管理**（升级/淘汰/合并）→ 本流程发现的问题最终流入 `/evolve`
> - `/skill-create` 负责**创建** Skill → 本流程负责**验收**已创建的 Skill

## 参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `scope` | `all` / `{skill-name}` / `new`（仅审计最近新增） | `all` |

## 步骤

0. **建立终点契约 (Task Contract)**
   > ⛔ **核心防御机制**
   - 在 `task.md` 中创建打卡项，覆盖步骤 1-7，全勾才可完结。

// turbo
1. **基线扫描 (Baseline Audit)**
   执行现有的自动化基线检查：
   ```bash
   bash .agent/scripts/skill-audit.sh .
   ```
   记录退出码。如退出码=2（存在严重缺陷），在报告中标记为 **BLOCKER**。

// turbo
2. **结构合规性检查 (Structural Compliance)**
   逐个 Skill 目录检查以下 **必要结构要素**：

   | 检查项 | 合规标准 | 严重级 |
   |--------|---------|--------|
   | YAML Frontmatter | 包含 `name`, `description`, `version` | ERROR |
   | 触发条件 | 明确描述何时激活此 Skill | WARN |
   | 输入/输出契约 | 定义 Skill 需要什么、产出什么 | WARN |
   | 步骤/流程 | 有编号步骤或清晰的执行流程 | ERROR |
   | 与现有体系关系 | 说明与其他 Skill/Rule/Workflow 的交互 | WARN |
   | 反模式/禁令 | 定义 Skill 不应做的事 | INFO |
   | 退出条件 | 明确何时算"完成" | WARN |

// turbo
3. **5 大维度主评分 (Primary Quality Score — 100 分制)**
   > 对照 skill-lint 原始内容的 5 大质量维度评分体系。

   | 维度 | 满分 | 核心关注点 |
   |------|------|-----------|
   | **清晰边界** (CB) | 25 | 输入输出和触发条件是否明确，Skill 职责边界是否清晰 |
   | **确定性执行** (DE) | 20 | 流程是否确定、步骤是否可预测 |
   | **可失败回退** (FF) | 15 | 异常处理和降级方案是否完备 |
   | **解耦可组合** (DC) | 20 | 依赖解耦、可被编排、不绑定特定模型或平台 |
   | **包完整性** (PI) | 20 | 包文件完整、无冗余、主子文件引用一致 |

   **评分规则**：
   - 维度内每条 ❌ 违规扣 4 分，⚠ 警告扣 2 分
   - 维度最低 0 分，不出现负分
   - **A 级 (90-100)**: 优秀，可直接使用
   - **B 级 (75-89)**: 良好，有小幅改进空间
   - **C 级 (60-74)**: 及格，存在明显问题需修复
   - **D 级 (0-59)**: 不合格，需重大重构

   **降级方案**: 如 lint-rules 读取失败 → 使用内置基础规则 (CB-01、DE-01、PI-01) 继续扫描，报告顶部注明降级提示。

3.5 **12 维度补充评估 (Supplementary Assessment)**
   > 在主评分基础上，按 1-5 分补充评估以下维度：

   | 维度 | 评估要点 |
   |------|---------|
   | **目标清晰度** | Skill 解决的问题是否一句话可描述 |
   | **边界明确度** | 与其他 Skill 的职责分割是否清晰 |
   | **可操作性** | 步骤是否可机械执行（非模糊指导） |
   | **可验证性** | 每步是否有可观测的完成标志 |
   | **幂等性** | 重复执行是否产生一致结果 |
   | **上下文效率** | Token 消耗是否合理（<400 行） |
   | **防御性** | 是否有错误处理和边界条件 |
   | **可组合性** | 是否能与其他 Skill/Workflow 组合 |
   | **可进化性** | 是否有明确的版本和变更历史 |
   | **一致性** | 与项目整体风格是否统一 |
   | **人机协作度** | 是否明确了哪些决策需要人类参与 |
   | **知识沉淀** | 是否将隐性经验显性化 |

4. **交叉引用验证 (Cross-Reference Validation)**
   - 检查 Skill 引用的所有路径（`*.md` / `*.sh`）是否**物理存在**
   - 检查 `router-tables.md` 中是否已注册该 Skill
   - 检查 AGENT.md 的规则路由是否覆盖该 Skill 的触发场景
   - 如 Skill 声称依赖其他 Skill/Rule，验证依赖目标存在且版本兼容

5. **冗余与冲突扫描 (Redundancy & Conflict Detection)**
   - 语义重复检测：两个 Skill 的核心职责是否 >70% 重叠
   - 指令冲突检测：两个 Skill 对同一场景是否给出矛盾指引
   - 输出：冲突对列表 + 合并建议

6. **进化建议生成 (Evolution Recommendations)**
   根据评估结果自动生成：
   - **D 级 Skill** → 建议淘汰或完全重写，生成具体重写要点
   - **C 级 Skill** → 列出必须修复的 TOP-3 维度，生成改进 Prompt
   - **B 级 Skill** → 列出可选优化项，优先级排序
   - **冗余 Skill** → 生成合并方案（保留哪个、合并哪些内容）
   - 高分 Skill 中的最佳实践 → 提取为 Skill 编写模板

7. **输出治理报告**

   ```markdown
   ## Skill 质量治理报告
   - **扫描范围**: [all / skill-name]
   - **扫描时间**: [timestamp]
   - **总计 Skill**: [N]
   - **扫描模式**: [只读扫描]

   ### 基线扫描结果
   - ✅ 通过: [X]  ⚠ 警告: [Y]  ❌ 错误: [Z]

   ### 5 大维度评分 (100 分制)
   | 维度 | 得分 | 违规项 |
   |------|------|--------|
   | 清晰边界 (CB) | [/25] | [详情] |
   | 确定性执行 (DE) | [/20] | [详情] |
   | 可失败回退 (FF) | [/15] | [详情] |
   | 解耦可组合 (DC) | [/20] | [详情] |
   | 包完整性 (PI) | [/20] | [详情] |
   | **总分** | [/100] | **等级: [A/B/C/D]** |

   ### 质量评级分布
   | 等级 | 数量 | Skill 列表 |
   |------|------|-----------|
   | A 级 | [N]  | [names]   |
   | B 级 | [N]  | [names]   |
   | C 级 | [N]  | [names]   |
   | D 级 | [N]  | [names]   |

   ### 交叉引用问题
   - [断链列表]

   ### 冗余/冲突
   - [冲突对及建议]

   ### 进化行动项
   1. [具体行动 + 优先级]
   ```

   - **检查终点契约**：确认打卡文件全部 `[x]` 后方可完结。

   **修复模式**（对照原始 Skill 的门控机制）：
   > 仅当用户明确说"帮我修复"、"fix"、"修复这些问题"时才进入修复模式。
   - 修复顺序：先 ❌ 违规（按维度），再 ⚠ 警告（按维度）
   - 修复方式：逐项修复，每次修复后重新读取确认
   - 无法自动完成的项：跳过并标注"需手动修复"

---

### 系统禁令 (Red Lines)
❌ 未运行 `skill-audit.sh` 就直接评估（缺少基线数据）
❌ 仅凭行数/格式判断质量（必须含内容维度评估）
❌ 自行删除或修改 Skill（只产出建议，变更由 `/evolve` 执行）
❌ 跳过交叉引用验证（断链 Skill 是重大隐患）
❌ 扫描过程中修改任何文件（只读原则）

如果阻塞，可求助 `/debug` 流程。
